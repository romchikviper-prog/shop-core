# Тести та збірка

## Одна команда

```bash
py -3 check.py
```

Скрипт послідовно запускає `mypy --strict src` і `pytest`. Якщо хоч одна перевірка не пройшла, повертає ненульовий код виходу.

Окремо:

```bash
py -3 -m mypy --strict src
py -3 -m pytest -q
```

## Результат на момент здачі

```text
$ py -3 -m mypy --strict src
Success: no issues found in 22 source files

$ py -3 -m pytest -q
143 passed
```

## Що саме зафіксовано тестами

- **Недопустимі переходи недоступні:** `Draft` не має `pay`/`ship`, `Placed` не має `ship`, `Paid` не має `cancel`, `Shipped`/`Cancelled` — термінальні. Це перевіряється і тестами `hasattr`, і `mypy` на `docs/type-safety/invalid_transition.py`.
- **Гроші:** від'ємна сума, `NaN`, `Infinity`, різна валюта й понад два знаки після коми відхиляються; `parse` не кидає винятків.
- **Склад:** резервування all-or-nothing; повторний резерв того самого замовлення ідемпотентний; звільнення повертає залишок; залишок не стає від'ємним.
- **Оплата:** успіх переводить у `Paid`; відмова лишає `Placed`; повторна оплата не викликає шлюз удруге; idempotency key стабільний між спробами.
- **Ціноутворення:** порядок «фіксована знижка → ПДВ» і «ПДВ → фіксована знижка» дає різні результати, тому порядок декораторів зафіксовано тестом.
- **Архітектура:** домен не залежить від інфраструктури; це перевіряється аналізом імпортів, а не лише домовленістю.

## Чого тести не перевіряють

- Реальний PostgreSQL, HTTP і конкурентність на рівні БД: у ЛР1 адаптери в пам'яті. Конкурентний перепродаж перевіряється на рівні агрегата й сервісу, а не реальними транзакціями БД.
- Реальний платіжний шлюз: використовується `SandboxLegacyPayClient` і тестові дублери.
- Продуктивність p95: у ЛР1 не вимірюється; сценарій QS-1 визначає архітектуру, а вимірювання — у наступних роботах.
